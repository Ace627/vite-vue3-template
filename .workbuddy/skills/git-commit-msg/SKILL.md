# 生成 Git 提交信息（5 候选 → 选择 → 确认提交）

根据当前工作区的实际改动，生成 **5 条候选**的单行中文 commit message，让用户挑选其一，再确认是否提交。

## 触发场景
- 用户说："生成 git 的 msg / 提交说明 / commit message"
- 用户要把"现在的改动"整理成提交信息

## 执行步骤
1. **确认仓库**：运行 `git status`。若提示 "not a git repository"，告知用户本仓库尚未 `git init`，询问是否要初始化（**不要擅自初始化**，除非用户明确同意）。
2. **收集改动**：
   - `git diff --staged --stat` 看已暂存改动
   - `git diff --stat` 看未暂存改动
   - 改动较多或语义不清时，用 `git diff`（或 `git diff --staged`）看具体代码
   - `git log --oneline -10` 了解项目既有提交风格/语言习惯
3. **生成 5 条候选**：基于真实改动，产出 5 条**彼此有差异**的单行 message（用不同 type 或不同侧重点，避免雷同），每条都符合 `<type>: <简述>` 单行格式。
4. **请用户选择**：以编号列表 `1-5` 文本展示 5 条候选，请用户回复编号选择**其中一条**。（注意：单行候选有 5 条，超过快捷选择组件的选项上限，因此用**纯文本列出**让用户回复编号，不要塞进只能放 4 项的组件。）
5. **再让用户选择提交方式**：用户选定 msg 后，**单独再问一次**，给出 3 个选项供选择（正好 3 项，可用快捷选择组件）：
   - **提交到暂存区**：`git commit -m "<所选 message>"`（仅本地提交，不推送）。
   - **提交并推送**：`git commit -m "<所选 message>"` 后执行 `git push`（推送前确认已配置 remote/上游；若无则提示用户处理）。
   - **跳过**：不执行任何写操作，结束，仅保留所选 message。
   执行写操作前，先 `git diff --staged --stat` 检查：
   - **有已暂存改动** → 按所选方式 commit（及 push）。
   - **无已暂存但有无暂存改动** → 先确认是否 `git add -A`（或指定文件）再继续，**不擅自 add**。
   - **工作区干净（无改动）** → 提示无可提交内容。
   - 若暂存区含 `.workbuddy/` 等工具内部目录，写操作前提醒用户是否要忽略，**不擅自处理**。
6. **所有写操作（add / commit）都必须用户确认**，不自动执行。

## message 格式
```
<type>: <简述>
```
- **每条候选都只输出这一行**，不要 body、不要分条、不要空行、不要解释。
- `<type>` 用小写英文（见下表）。
- `<简述>` 用中文，动词开头，聚焦"做了什么"，不超过 50 字，**不加句号**。

## type 选择参考
| type | 含义 | 示例 |
|---|---|---|
| feat | 新功能 | 新增登录页 |
| fix | 修复 bug | 修复路由白屏 |
| chore | 构建/工程/杂项（无功能变更） | 初始化模板骨架、清理 demo |
| docs | 文档 | 补充 README |
| refactor | 重构（不改行为） | 抽离工具函数 |
| style | 样式/格式（不影响逻辑） | 调整主题色 |
| test | 测试 | 补充单测 |
| perf | 性能 | 优化列表渲染 |
| build | 构建配置 | 新增 vite 别名 |
| ci | CI 流程 | 新增流水线 |

## 示例
用户输入："生成 git 的 msg"
输出（5 条候选，请回复编号选择）：
```
1. chore: 初始化前端工程化模板基础骨架
2. build: 搭建 vite 工程化模板起步结构
3. refactor: 清理 create vite 默认 demo 产物
4. chore: 建立模板基础脚手架与样式规范
5. feat: 初始化可扩展的前端工程化模板
```
用户回复选 `1` → 再询问提交方式（提交到暂存区 / 提交并推送 / 跳过）→ 用户选"提交并推送" → `git commit -m "chore: 初始化前端工程化模板基础骨架"` 后 `git push`。

## 注意
- **每条候选仅单行**，5 条之间也彼此不同（不同 type 或不同侧重点）。
- **两步确认**：先选 msg，再单独选择提交方式（提交到暂存区 / 提交并推送 / 跳过）；两步都要用户主动回复。
- **真实优先**：基于 `git diff` 核实，不臆测、不编造未发生的改动。
- **语言**：message 以中文为主，type 保留英文。
- **不擅自写操作**：add / commit / push 必须用户确认后执行。
