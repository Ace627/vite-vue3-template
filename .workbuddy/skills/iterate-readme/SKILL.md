# 迭代 README（iterate-readme）

把 README.md 持续维护为一份**可对外展示的前端工程化实践样本**：结构稳定、语气统一、能力清单与 `docs/前端工程化.md` 对齐，且严格规避"简历"字样。

## 核心主旨（本项目已定稿，迭代时务必遵守）

README 的定位不是"功能清单"或"业务应用说明"，而是：

- **一句话定位**：一份**可展示的前端工程化实践样本**——用 Vue 3 + TypeScript + Vite 的最小骨架，把常见工程化手段逐项落地、跑通、并讲清理由。
- **三个锚点**（写/改文案时反复对照）：
  1. **逐项落地、可运行、可解释**：每一项配置都能在代码里看到实现、在文档里读到「为什么这么配、带来了什么收益」。
  2. **可验证样本**：配置真实可用、决策有依据、收益可量化。
  3. **用途指向**：适合用于技术分享、团队复盘或能力佐证（用中性表述，绝不直接说"简历"）。
- **硬约束**：全文（标题/正文/表格/注释）**不得出现"简历"二字**；历史遗留须在迭代时删除并换中性表述。

## 触发场景

- 用户说："迭代一下 README" / "按这个主旨更新 README" / "README 同步一下工程化改动" / "维护 README 的工程化样本定位"
- 项目新增/变更了工程化配置（如新增 Skill、改了构建策略、动了 Element Plus 等），需要让 README 的能力清单与 `docs/前端工程化.md` 同步
- 用户显式调用本 Skill

## 输入

- （可选）本次工程化改动的范围说明；无则说明则自动 diff `docs/前端工程化.md` 与当前 README 能力表，找出差异。

## 前置约定（切勿擅自改动）

- **目标文件**：`README.md`（仓库根）。
- **配套文件**：`docs/前端工程化.md` 是"配置详解"——README 负责"展示什么、为什么值得看"，docs 负责"逐条展开为什么、收益几何"。两者关系在 README 的「这份样本展示了什么」表格下方引导语、以及 docs 顶部引导语中交叉呼应，迭代时保持该呼应。
- **结构骨架**（README 必须包含以下段落，顺序固定）：
  1. 顶部 tagline（引用块）：一份**可展示的前端工程化实践样本**……
  2. 引言段：非业务应用 + 三个锚点（可运行/可解释、可验证样本、用途指向）。
  3. 「这份样本展示了什么」能力域↔落地手段对照表（见下「能力域清单」）。
  4. 「它适合用来做什么」/「它不适合做什么」。
  5. 「快速开始」（含 pnpm 不可用时的本地二进制兜底注记）。
  6. 「延伸阅读」表（docs/前端工程化.md + AGENTS.md）。
  7. 「项目级 Skill」一句话指引。
- **术语**：中文为主，技术关键词（Vue / TypeScript / Vite / Pinia / gzip / `ApiResponse<T>` 等）保留英文。

## 执行步骤

1. **读取现状**：读 `README.md` 与 `docs/前端工程化.md`（只读）。
2. **自检硬约束**：grep README 是否含"简历" → 有则列入待删项。
3. **对齐能力清单**：比对 README「这份样本展示了什么」表的行，与 docs 八个章节标题；发现新增/缺失/措辞漂移 → 记录差异。
4. **对照主旨**：检查 tagline、引言三锚点、用途表述是否仍贴合「核心主旨」；有语气漂移（如写成纯功能罗列、出现"作品集/简历"类词）则记录。
5. **先出方案**：把上述差异整理成**具体改动清单**（哪段、旧→新、为什么），回给用户确认 —— **不立即改文件**。
6. **等确认**：用户明确说"落地/执行/开始"后再改；否则只给方案。
7. **落地改动**：按确认后的清单编辑 `README.md`（必要时同步 docs 顶部引导语或新增章节）。保持结构骨架与术语约定。
8. **二次核验**：改完再 grep 一次"简历"确保 0 命中；确认能力表与 docs 章节对应无遗漏。
9. **输出小结**：列明改了哪些段、是否同步了 docs、是否清除了"简历"字样。

## 约束

- 不自动 `git commit`；不动与本次无关的其它文件（除非用户要求同步 docs 正文）。
- 保持 README 的"样本/展示"语气，不退化成普通功能文档或业务说明。
- 所有改动中文注释/文案为主，技术关键词保留英文。

## 风险与注意

- **"简历"字样红线**：任何迭代都不得引入该词；历史文本若含此词必须清除。
- **能力表与 docs 漂移**：docs 是真相源（逐条展开），README 表是摘要；以 docs 章节为准做对齐，不要反向把 README 的简写写回 docs。
- **结构骨架顺序**：段落顺序固定，新增内容放进对应段落，不要另起无关章节破坏"样本"阅读节奏。

## 验证

- README 中 grep "简历" → 0 命中。
- README「这份样本展示了什么」表的每一行，都能在 `docs/前端工程化.md` 找到对应章节。
- tagline 与引言三锚点文案完整、语气贴合"可展示的工程化实践样本"。
