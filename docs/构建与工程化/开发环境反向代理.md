# 开发环境反向代理

## 功能定位

开发期借助 Vite 内置 dev server 的 `server.proxy`，把前端发往「代理前缀 + 后端公共路径」的请求在 Node 侧转发到真实后端，浏览器侧就不存在跨域问题。生产构建产物不含代理逻辑，由 nginx / 网关等同域反向代理接管。

## 实现要点

| 落地点 | 职责 |
| --- | --- |
| `vite.config.ts` 的 `server.proxy` | 代理核心配置；以 `VITE_BASE_API` 作匹配前缀，`target` 指向 `VITE_BASE_URL`，`changeOrigin: true`，`rewrite` 剥离 `/dev-api` |
| `.env.development` | `VITE_BASE_URL="http://localhost:3000"`（后端地址）、`VITE_BASE_API="/dev-api/api"`（触发前缀 `/dev-api` + 后端路径 `/api`） |
| `.env.production` | 仅 `VITE_BASE_API="/api"`，不设 `VITE_BASE_URL`（生产无代理目标） |
| `src/utils/request/index.ts` | axios `baseURL: import.meta.env.VITE_BASE_API`，请求前缀由环境变量驱动 |
| `src/types/global/vite-env.d.ts` | 声明 `VITE_BASE_URL` / `VITE_BASE_API`，提供 TS 类型提示 |

### 机制

开发期一次请求 `/dev-api/api/xxx` 的流转：

```
浏览器 ──(同源 localhost:5173，无 CORS)──▶ Vite dev server
        proxy 匹配 /dev-api/api
        → changeOrigin 改写 Host
        → rewrite 剥离 /dev-api
        ──▶ http://localhost:3000/api/xxx   (Node 侧转发，不受浏览器跨域限制)
```

`VITE_BASE_API` 把「代理触发前缀 `/dev-api`」与「后端公共路径 `/api`」合一：
- 开发期值为 `/dev-api/api` → 命中代理、剥离 `/dev-api` → 后端收到 `/api/...`；
- 生产期值为 `/api`（无 `/dev-api`）→ 不触发代理，请求同源直连 `/api`。

## 好处

- 开发期零跨域：浏览器只与同源 dev server 通信，跨域发生在服务端，不用后端开 CORS、也不用浏览器插件。
- 切环境或换后端只动 `.env`，业务代码和 axios 实例零改动；后端要新增公共路径，在 `/dev-api` 后追加即可（如 `/dev-api/common`）。
- `VITE_BASE_API` 一处同时驱动「代理匹配键」「axios baseURL」「rewrite 剥离」三处。后端没有公共路径时（接口即 `/user/list`，而非 `/api/user/list`），把值写成 `/dev-api`、去掉 `/api` 段即可：代理匹配键与 baseURL 同步变为 `/dev-api`，rewrite 剥离后转发到 `localhost:3000/user/list`，不碰 `vite.config.ts`、不改 axios、不改 rewrite，全局自动生效。

## 工程化好处

- 网络转发配置与业务请求代码解耦，前端无需感知后端部署地址。
- dev（代理转发）与 prod（同源直连）由 `.env` 分流；代理逻辑不进生产包，产物更干净。
- `vite-env.d.ts` 对两个变量做了声明，避免拼写和取值错误。

## 注意事项

- Vite 代理仅开发期生效；生产必须由 nginx / 网关做同域反向代理（`.env.production` 的 `/api` 直连同源后端或网关）。
- `VITE_BASE_URL` 仅 dev 存在，生产不应设置，否则无意义。
- `rewrite` 只剥离 `/dev-api`；后端公共路径不是 `/api` 时，需同步改 `.env.development` 与 `.env.production` 的 `VITE_BASE_API`。
- `changeOrigin: true` 务必开启，否则部分后端会按 `Host` 头拒绝请求。
- 本项目定位「纯前端 mock，不接后端」，当前 `VITE_BASE_URL` 的 `localhost:3000` 是模板占位；切换真实后端时改 `.env` 即可，业务代码无需改动。
