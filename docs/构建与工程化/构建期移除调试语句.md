# 构建期移除调试语句

## 功能定位

生产构建（minify 阶段）通过 Rolldown 的 `compress` 选项，把 `console.*` 调用与 `debugger;` 语句从产物中剔除。本文只谈「构建期移除调试语句」这一项优化，不涉及分包、传输压缩等其他构建处理。

## 实现要点

| 落地点 | 职责 |
| --- | --- |
| `vite.config.ts` `build.rolldownOptions.output.minify.compress.dropConsole` | 移除所有 `console.*` 调用；值为 `VITE_DROP_CONSOLE !== 'false'`，即默认启用 |
| `vite.config.ts` `build.rolldownOptions.output.minify.compress.dropDebugger` | 移除所有 `debugger;` 语句；值为 `VITE_DROP_DEBUGGER !== 'false'`，即默认启用 |
| `.env.production` | `VITE_DROP_CONSOLE="true"` / `VITE_DROP_DEBUGGER="true"`，显式开启生产剔除 |
| `.env`（基础配置） | 未声明这两个变量时，代码侧默认判定为启用（除非显式写 `'false'`） |

### 机制

- 该处理发生在 `vite build` 的 minify 压缩阶段，仅作用于生产构建产物；dev server 不执行 minify，开发期日志与断点照常保留。
- `dropConsole` 删除全部 `console.log/info/warn/error/...` 调用节点；`dropDebugger` 删除 `debugger;` 语句节点。两者都是「删除语句」，被移除的代码不会产生任何运行时调用。
- 开关由 `VITE_DROP_*` 环境变量驱动：默认启用，设为 `'false'` 即保留（例如临时构建一个带日志的排查包）。

## 好处

- 调试日志常含内部变量、接口路径、业务细节，移除后不暴露给终端用户，降低敏感信息外泄风险。
- 开发期若打了大量 `console.log`，成批删除可明显减小 JS 产物体积。
- 生产残留 `debugger;` 会在用户浏览器拉起 DevTools 或暂停执行，移除后彻底消除该隐患。
- `console.*` 本身有调用与格式化成本，删除后减少生产环境不必要的主线程占用。
- 生产构建不再依赖是否「手滑留了调试语句」，产物行为稳定一致。
- `console.log` 会在 DevTools 中保留被打印对象的引用、阻碍 GC；长会话 SPA 中大量日志可能累积内存，移除后消除这一引用持有风险。
- Sentry 等监控常自动捕获 `console.error`；移除调试日志后，仪表盘只反映真实错误，告警更准、误报更少。

## 工程化好处

- 剔除在构建期完成，产物中不含任何拦截/替换逻辑，不增加运行时负担。
- 经 `VITE_DROP_*` 即可按环境开关，排查生产问题时可临时保留日志重新构建，无需改代码。

## 注意事项

- 仅生产构建生效：dev 不受影响，开发期日志照常输出，方便本地调试。
- 默认启用：未显式设 `'false'` 即剔除；若要保留日志，必须显式 `VITE_DROP_CONSOLE='false'`。
- 不要依赖 `console` 做生产关键逻辑：被移除后相关逻辑会消失，关键输出应走专用日志/上报通道。
- 与 sourcemap 无关：`sourcemap:false` 是另一项独立配置，不在此范畴。
- `dropConsole` 是全量删除：不会区分日志级别，所有 `console.*` 一并移除。
