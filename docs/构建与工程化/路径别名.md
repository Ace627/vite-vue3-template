# 路径别名

## 功能定位

`@/*` 把 `src` 目录提升为稳定的导入根：业务代码引用模块时统一写 `@/utils/xxx`、`@/components/Xxx`、`@/views/...`，不再写 `../../../` 这类随当前文件位置漂移的深层相对路径。本质是编译期路径重写——Vite 在打包时把别名内联成真实相对路径，TypeScript 在类型检查期按 `paths` 解析，产物不含任何额外运行时代码（零开销）。

## 实现要点

| 落地点 | 职责 |
| --- | --- |
| `vite.config.ts` `resolve.alias` | 运行期解析：`'@' → fileURLToPath(new URL('./src', import.meta.url))`；用 `import.meta.url` 拼出 `src` 绝对路径，ESM 下避免 `__dirname` 失效 |
| `tsconfig.app.json` `compilerOptions.paths` | 类型期解析：`"@/*": ["./src/*"]`；让 TS / IDE 识别别名，跳转与智能提示生效 |
| 二者关系 | 双向同步是硬约束：只改一边，要么 IDE 报错（tsconfig 有、vite 无），要么运行时 404（vite 有、tsconfig 无） |

### 机制

- 写代码时统一用 `@/` 引用；TS 语言服务按 `paths` 解析类型与跳转，构建时 Vite / Rolldown 按 `resolve.alias` 把 `@/` 重写成真实路径后再打包。
- `paths` 仅影响类型期；真正决定产物模块关系的是 `vite.resolve.alias`。两者必须指向同一目录（`src`），口径不一致即报错或 404。

## 好处

- `../../../../` 随文件被移动、目录层级调整极易断裂，且难以一眼判断指向；`@/` 永远指向 `src` 根，与当前文件位置无关，挪动文件不必重写引用。
- 调整目录结构或迁移模块时，相对路径需全局替换且易漏，别名引用零改动即自动跟随。
- `@/` 一眼可知是项目源码根，不必反推「当前文件在第几层」，阅读与 Code Review 更顺。
- 所有导入走同一根，IDE 跳转、TS 解析、构建解析三者行为一致，不出现「本地能跳、构建找不到」的分裂。
- `tsconfig.paths` 让 TS 真正识别别名，编辑器智能提示、跳转、重命名生效，避免字符串路径的隐性错误。
- 相对路径易写错层级（少一个 `../` 指向兄弟、多一个指向父级），别名无此问题。
- `@/utils` `@/components` `@/views` `@/store` `@/hooks` 等约定，天然把代码按职责分区，结构自解释。
- 别名 + barrel 共同构成「单一入口」：业务只 `import { xxx } from '@/utils'`，呼应 AGENTS.md 的 `@/utils` 唯一入口红线。
- 别名是编译期重写，产物中已展开为真实路径，不引入任何 resolver / 运行时依赖。
- 开发预览与生产构建都走同一 `resolve.alias`，解析同源，本地所见即线上所得。
- `@/components/UserCard` 比 `../../../components/UserCard` 更短更干净，文件头 import 区更易读。

## 工程化好处

- 路径约定集中在一处配置，模块位置与引用方式解耦。
- 改源码根目录（如从 `src` 换名）只需同步 `vite.config.ts` 与 `tsconfig.app.json` 两处，不动业务代码。
- 类型期（`tsconfig`）与运行期（`vite`）各管一段，职责清晰、互不影响。
- 别名强制统一入口，与 AGENTS.md 的「复用 `@/utils`、统一从 `@/utils` 导入」红线一致，约束被写进配置而非靠口头约定。

## 注意事项

- 双向同步缺一不可：`vite.resolve.alias` 与 `tsconfig.paths` 必须同时配置且指向同一目录；只改一边会 IDE 报错或运行时 404。
- `vite.config.ts` 用 `fileURLToPath(new URL('./src', import.meta.url))` 而非 `__dirname`（ESM 下 `__dirname` 不存在）；这是 Vite 官方推荐写法。
- `paths` 仅类型期：它不参与打包，真正解析靠 Vite；不要误以为配了 `paths` 运行期就认。
- 不要为「好看」改用绝对磁盘路径：别名应保持 `@/* → ./src/*` 的相对项目根形式，避免把本地绝对路径写死进配置（换机器 / CI 即失效）。
- 与自动导入不冲突：`unplugin-auto-import` 自动导入的是 `vue/pinia` 等 API 名称，与 `@/` 路径别名是正交的两套机制，可并存。
