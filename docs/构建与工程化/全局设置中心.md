# 全局设置中心

## 功能定位

集中定义、读写与持久化全站可配置项（`SystemSetting`），是「配置单一可信源 + Pinia 状态 + 本地持久化」的闭环。组件与页面不直接碰 `localStorage`，统一经 store 读写，刷新后自动还原。

## 实现要点

| 落地点 | 职责 |
| --- | --- |
| `src/defaultSettings.ts` | 定义 `SystemSetting` 类型与 `defaultSettings` 默认值，共 9 项：`theme` / `size` / `showDynamicTitle` / `uniqueOpened` / `showWatermark` / `showLogo` / `showTagsView` / `showTagsViewIcon` / `transition` |
| `src/store/modules/setting.ts` | `useSettingStore` 用 `merge({}, defaultSettings, getSystemSetting())` 初始化；暴露各字段 + `saveSetting` / `resetSetting` / `isDark` / `showSetting`（控制配置抽屉显隐） |
| `src/utils/cache/system-setting.cache.ts` | 基于 `StorageCache` 的领域封装：`setSystemSetting` / `getSystemSetting` / `removeSystemSetting`（key 走 `app:storage:` 前缀） |
| `src/hooks/useTheme.ts` | 主题即时保存入口：`applyTheme` 内调用 `saveSetting({ showTip: false })` |
| `src/layout/components/SettingPanel/index.vue` | 设置 UI：右侧 `el-drawer` 抽屉，内 `el-switch` / `el-select` 双向绑定 `settingStore` 各字段，底部「保存/重置」按钮统一 `saveSetting` / `resetSetting` |

## 好处

- **集中默认值**：所有可配置项在 `defaultSettings` 一处定义，新增配置只改一处。
- **配置中心化**：组件不直接读写 `localStorage`，统一走 store，避免散落。
- **持久化透明**：写入 `StorageCache('systemSetting')`，刷新后 `merge` 还原。
- **即时 / 延迟双模式**：主题即时保存，其余开关在 `SettingPanel` 抽屉内预览式修改，由「保存配置」按钮统一落盘。
- **抽屉式交互**：`SettingPanel` 以右侧 `el-drawer` 呈现，齿轮图标 / 用户菜单「系统设置」唤起，不打断当前页面。

## 工程化好处

- **单一可信源（Single Source of Truth）**：类型 + 默认值 + 持久化形成闭环。
- **与 Pinia 状态层协同**：`state` 响应式，`isDark` 等派生值被 layout / 水印 / 主题切换统一消费。
- **解耦 UI 与存储**：UI 只改 store，落盘由 `saveSetting` 负责，职责清晰。
- **可扩展**：新增配置项只需在 `defaultSettings` 加字段 + store `state` 同步，消费方只读 store。
- **可复制**：是前端「运行时配置中心」的标准范式。

## 注意事项

- `saveSetting(config?)` 默认 `showTip: true`（弹 loading）；即时保存（如主题）传 `false` 避免闪烁提示。
- `resetSetting()` 清缓存后 `reload`（非热更新），重置即用。
- 初始化 `merge` 顺序：`getSystemSetting()` 覆盖 `defaultSettings`，本地值优先于默认值。
- 主题即时保存必须放在 `startViewTransition` 的 `run` 回调内、且主题值已更新之后（见 `../用户体验/主题切换.md`），否则持久化旧主题。
- 持久化体为 `toRaw(state)`，写入的是纯数据快照。
- `showSetting` 控制 `SettingPanel` 抽屉显隐：Navbar 齿轮与用户菜单「系统设置」将其置 `true` 打开抽屉，关闭抽屉不影响已保存配置。
