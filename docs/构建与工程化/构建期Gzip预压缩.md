# 构建期 Gzip 预压缩

## 功能定位

生产构建阶段用 `vite-plugin-compression2` 对产物做 gzip 预压缩：在构建机一次性把文本类静态资源压成 `.gz` 兄弟文件，随包发布；运行时由服务端（`gzip_static` / CDN 预压缩）直接发 `.gz`，浏览器原生解压。本文只谈「构建期 gzip 预压缩」这一项，不涉及分包、移除调试语句等其他构建处理。

## 实现要点

| 落地点 | 职责 |
| --- | --- |
| `build/plugins/dist-compression.ts` | `setupCompressionPlugin()` 核心配置：`algorithms: [['gzip', { level: 9 }]]`、`threshold: 10*1024`、`deleteOriginalAssets: false`、`include: /\.(js|css|json|html|ico|svg)/i`、`logLevel: 'silent'` |
| `build/plugins/index.ts` | 注册 `setupCompressionPlugin()`，仅生产构建生效 |
| 构建产物 `dist/` | 每个命中的源文件旁生成同名 `.gz`（如 `vue-<hash>.js` → `vue-<hash>.js.gz`），原文件保留 |

### 机制

- 构建时扫描输出文件，对后缀匹配且体积 `> 10KB` 的文本资源，用 gzip level 9 生成 `.gz` 兄弟文件；原文件不动。
- 请求链路：

```
浏览器请求 app.js，带 Accept-Encoding: gzip
   → 服务端（nginx gzip_static / CDN 预压缩）命中 app.js.gz
   → 直接返回 .gz（响应头 Content-Encoding: gzip）
   → 浏览器原生解压、执行
（若服务端未开 gzip_static → 回退返回原 app.js，不影响可用）
```

- 压缩在构建期完成一次，服务端不再实时压缩；`.gz` 仅当客户端支持且服务端开启对应能力时才被使用。

## 好处

- 传输体积大幅下降：gzip 对 JS/CSS 等文本压缩率通常 60%~70%（如 vue 60.7KB→23.6KB、vue-router 22.7KB→8.9KB，约 61%）。首屏大资源下载更快、流量更省，移动端 / 按量计费场景收益明显。
- 压缩成本前移到构建期：CI / 构建机一次性完成，线上服务器不必对每个请求实时压缩，省 CPU、响应更快；客户端解压由浏览器原生完成，无前端 JS 开销。
- 更小的传输体量直接缩短下载时间，弱网、高延迟下首屏指标（LCP / FCP）改善明显。
- `deleteOriginalAssets: false` 让服务端未开 `gzip_static` 时仍能发原文件，不会因缺 `.gz` 而 404，便于灰度回退。
- 小文件压了省不了多少、甚至可能因头信息略增，跳过它们（阈值 10KB）避免无用产物，聚焦大资源收益。
- 图片 / 字体通常已自带压缩，排除在 `include` 之外，不浪费构建时间、不产生冗余产物。
- 前端静态资源一次压缩、长期服务，用 level 9 换最小体积，构建略慢但长期划算。
- 分包后每个 chunk 内容更纯粹（如纯 vue），gzip 对其压缩率更高，分包 + 预压缩两层收益叠加。
- 预压缩 `.gz` 可被 CDN 直接缓存与回源分发，边缘节点无需实时压缩，命中与回源都更高效。
- gzip 是 HTTP 标准、浏览器原生解压，前端产物不需引入任何解压库，零运行时依赖。
- 传输体量下降直接减少出口带宽，对按流量计费的云主机、CDN 是实打实的费用节约。
- 免去服务端实时压缩，避免大请求下 CPU 毛刺与压缩导致的延迟抖动，峰值流量时响应更平稳。

## 工程化好处

- 压缩是构建期产物处理，不侵入业务代码，也不增加运行时负担。
- 算法（gzip / brotli 等）、等级、阈值、后缀名单均可调，未来切 brotli 只改一处配置。

## 注意事项

- 必须服务端开启 `gzip_static`（nginx）或 CDN 预压缩，否则 `.gz` 不会被使用、仍发原文件，这是该方案生效的前置条件。
- 仅生产构建生效：dev server 不跑压缩，本地调试拿到的仍是未压缩资源。
- dist 体积会因双份文件变大：`.gz` 与原文件并存，磁盘占用增加，但传输阶段只用 `.gz`，不影响用户侧下载量。
- 与 `构建文件拆分`、`移除调试语句` 是三件独立优化：本篇只管「传输压缩」，分包管「拆成哪些块」、剔除管「去掉调试语句」，三者互补不重叠。
- 阈值 / 算法可按需调整：如资源普遍偏小可调低 `threshold`，或评估引入 brotli（本项目明确不引入 brotli，gzip 已足够）。
