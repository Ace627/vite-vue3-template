# 前端工程化配置

> 基于 `pnpm create vite` 的 Vue3 + TS 模板二次改造，以下为已实现的工程化配置。每条后用一句话说明它带来的好处。本文是 [`README.md`](../README.md) 中"前端工程化实践样本"的**配置详解**：样本展示"配了什么、为什么、收益几何"，这里逐条展开。

## 零、前端工程化解决了什么问题

当项目从「一个人写几页」长成「一个团队维护成千上万行、还要持续交付」时，靠人肉约定再也撑不住。前端工程化就是把「靠人自觉」变成「靠系统兜底」——它不是某一项技术，而是一整套让「开发 — 构建 — 协作 — 交付」可重复、可预期的体系，主要应对以下六类问题：

| 工程化前痛点 | 工程化解法 | 本模板对应能力 |
| --- | --- | --- |
| 文件混乱、全局变量污染 | 模块化 / 组件化 / 目录约定 | 路径别名 `@/`、AGENTS.md 目录约定、组件化分层 |
| 改一行刷新整页 | Dev Server + HMR 热更新 | Vite 极速 HMR |
| 手写重复样板代码 | 脚手架 + 自动导入 + UI 库 | unplugin 自动导入、Element Plus、SvgIcon |
| 上线慢、包体大 | 打包 / Tree-shaking / 分包 / 压缩 | vendor 分包、gzip 预压缩、drop console/debugger |
| 运行时才报错 | TypeScript + Lint + 单测 | 严格 TS、oxfmt、vue-tsc 校验 |
| 协作风格打架 | 规范 + Git Hooks | AGENTS.md 约束、oxfmt（husky 待补） |

下文逐条展开本模板已落地的工程化配置与其收益。

## 一、构建与产物优化

- **构建期 vendor chunk 分包（Rolldown `codeSplitting.groups`）**：把 `vue/pinia/vue-router/axios/dayjs` 拆成独立带 hash 的 chunk，库代码不随业务发版变动，二次访问命中浏览器长缓存、免重下，首屏多块并行下载更快。
- **构建期 gzip 预压缩（vite-plugin-compression2）**：对 >10KB 的 JS/CSS/JSON/HTML/SVG 生成 `.gz` 预压缩文件（保留原文件），传输体积降约 61%（vue 60.7KB→23.6KB、vue-router 22.7KB→8.9KB），首屏大资源下载更快；压缩成本前移到构建期、零运行时开销，服务端开 `gzip_static` 即直接发 `.gz`。
- **构建期移除 console/debugger**：通过 Rolldown `minify.compress.dropConsole/dropDebugger` 在打包时剔除调试语句，生产包更干净、体积更小（可用 `VITE_DROP_*` 关闭）。
- **Vite 插件抽离**：vue / UnoCSS / 自动导入 / SVG 等插件统一在 `build/plugins/index.ts` 注册，配置集中可维护，且纳入 `tsconfig.node` 类型检查。

## 二、类型与代码质量

- **严格 TypeScript 配置**：开启 `noUnusedLocals/Parameters`、`erasableSyntaxOnly`，`tsconfig.node` 用 `verbatimModuleSyntax/nodenext`，编译期即拦掉未用变量与错误模块写法，减少低级 bug。
- **oxfmt 统一格式化**：固定 `printWidth/singleQuote/semi/trailingComma` 等规则（import 排序当前未启用），团队提交风格一致，`format:check` 可作格式门禁。
- **脚手架清理**：移除 Vite 默认样板冗余，保留最小可运行骨架，模板更干净、上手更快。

## 三、开发体验

- **路径别名 `@/*`**：`@` 直指 `src`，深层引用不再写 `../../`，且 tsconfig 与 vite alias 双向同步，IDE 跳转与构建都认。
- **unplugin 自动导入**：`vue/pinia/vue-router` 及 `store/modules`、`hooks` 免手写 import，减少样板、避免遗漏。
- **开发期反向代理 `/dev-api`**：把「代理触发前缀」与「后端公共路径」合一于 `VITE_BASE_API` 一个变量，开发消跨域、切环境/换后端只动 `.env`，业务代码零改动。
- **多环境 `.env`**：dev/prod 分别提供后端地址、超时、丢弃调试等变量，`index.html` 用 `%VITE_APP_TITLE%` 原生注入，环境切换零代码改动。

## 四、状态管理与路由

- **Pinia 状态管理**：`createPinia()` 单例 + `setupStore(app)` 统一装配，状态层结构清晰、便于测试与维护。
- **vue-router 三层结构 + 登录态守卫**：①`src/router/index.ts` 异步 `setupRouter(app)`（注册守卫→`app.use(router)`→`await router.isReady()` 再挂载），`VITE_ROUTER_MODE` 切换 hash/history；②`src/router/modules/static.route.ts` 抽离常量路由 `STATIC_ROUTE_LIST`（dashboard/login/404 通配），无动态权限；③`src/router/router.guard.ts` 的 `globalRouterBeforeGuard` 统一登录态拦截——白名单 `/login` 直接放行，无 token 跳 `/login?redirect=原路径`，登录后自动回跳。受保护页无需各自判权限，路由层兜底。
- **登录 / 登出（模拟实现）**：`login.vue` 写死 token 跑通「无 token→拦登录→登录→回跳→登出清 token」整链；目前是前端模拟（不调真实接口、不校验账号密码、无 roles 动态权限），接真实后端只需替换 `login.vue` 的 token 写入并补 `user` store。

## 五、请求层

- **axios 请求层**：统一实例 + `jwt-auth` / `response-transform` / `response-error` 三拦截器，成功自动解包 `data`、业务失败与 401 自动清 token 刷新；`ApiResponse<T>` 契约让调用方直接 `get<User>` 拿到业务数据，类型全程收紧。

## 六、样式与 UI

- **UnoCSS**：`presetWind3 + presetAttributify` + 自定义 rules/shortcuts，原子化开发、编译期摇树，无运行时 CSS 框架体积。
- **样式分层（reset.css）**：`reset.css` 经 `<link>` 引入不进打包，避免 FOUC（样式闪烁），全局样式入口 `index.scss` 独立清晰。
- **业务路由页基础容器 `.app-content`**：`src/styles/index.scss` 定义 `.app-content`（`position:relative; width:100%; padding:16px`），移动端 `html[data-device='mobile']` 收窄为 `12px`；所有挂载在 layout 内的业务路由页根元素统一加该类，页面内不再各自写 `padding`/`min-height`，保证内边距体验一致；移动端断点由 `src/hooks/useResize.ts` 在 `App.vue` 挂载时监听窗口宽度（阈值 768px），将 `appStore.device` 写入 `html[data-device]`，驱动各处的 `html[data-device='mobile']` 覆盖样式（如 `.app-content` 收窄、设置页行纵向堆叠）。
- **SVG 图标（SvgIcon）**：`vite-plugin-svg-icons` 通过 `virtual:svg-icons-register` 运行时注入 sprite，组件按文件名引用图标；新增图标走清理脚本适配 `currentColor`，单色图标随主题变色。
- **Element Plus（按需引入 + sass 主题 + 暗黑 css-vars + 主题切换开关）**：两插件互补、缺一不可。`unplugin-vue-components` + `ElementPlusResolver({ importStyle: 'sass' })` 负责**模板组件** `<el-xxx>` 与 sass 源样式按需自动导入（非全量引入，主 CSS 仅约 13KB、无 EP 独立 vendor chunk，佐证按需）；`unplugin-auto-import` 同一 resolver 仅自动导入 `ElMessage` 等 API 的**名称**。`unplugin-element-plus({ useSource: true })` 负责**函数式 API 的样式注入**——`ElMessage` / `ElMessageBox` / `ElNotification` / `ElLoading` 这类从 `'element-plus'` 显式 import 的函数，其样式 resolver 不会注入、必须靠它（曾误删导致 `ElMessage` 样式丢失，已恢复）。`vite.config.ts` 的 `additionalData` 把 `el-theme-light.scss` 的自定义主题变量（`@forward 'element-plus/theme-chalk/src/common/var.scss' with (...)`，primary `#0077ff` 等）注入每个 EP 组件样式编译完成换肤；`el-theme-dark.scss` 引入官方暗黑 css-vars（`html.dark` 下生效），已由 `Navbar` 的 `ThemeSwitch` 组件接好开关，主题切换可用。

- **品牌标识组件（AppLogo）**：项目 Brand（logo + 应用标题）的抽离封装组件，将品牌展示从布局中独立出来，可任意拼装复用、不依赖全局状态。路径 `src/layout/components/AppLogo/`（index.vue + types.ts）；props `showTitle`（默认 `true`，如侧边栏折叠时传 `false` 只显示图标）/`title`（默认 `import.meta.env.VITE_APP_TITLE`）；logo 用 `<img src="/favicon.svg">` 加载品牌图（属品牌图、非 UI 功能图标，不冲突 SvgIcon 规范）；当前 Navbar 中以 `<AppLogo :show-title="!appStore.isCollapse" />` 使用。
- **主题切换（亮 ↔ 暗）**：`src/defaultSettings.ts` 定义 `SystemSetting{theme, size, showDynamicTitle, showWatermark, transition}`（字段：`theme` 明暗、`size` 组件尺寸 `default | small | large`、`showDynamicTitle` 动态标题开关、`showWatermark` 全局水印开关、`transition` 路由转场动效，6 选 1，默认 `fade-transform`）；`store/modules/setting.ts` 的 `useSettingStore` 用 `merge(defaultSettings, getSystemSetting())` 初始化并提供 `isDark` / `saveSetting` / `resetSetting`；`src/hooks/useTheme.ts` 的 `useTheme()` 是主题切换的**统一逻辑层**——Navbar 的 `ThemeSwitch` 与设置页都委托它，负责命令式同步 `html.dark` 类、View Transitions API 圆形扩散动效（有点击坐标从点击点扩散、无坐标从屏幕中心）、防 FOUC 初始化、非 Chromium 浏览器自动降级；持久化经 `saveSetting` 写入 `StorageCache('systemSetting')`（刷新后保持）；`useDynamicTitle` 已支持 `showDynamicTitle` 动态标题开关，并已由设置页接入。
- **设置页 `/settings`**：路由已在 `src/router/modules/static.route.ts` 的 `STATIC_ROUTE_LIST` 注册为 layout 子路由，Navbar 右侧以 `SvgIcon name="Setting"` 入口跳转。页面提供五项设置——①**主题模式**：复用 `useTheme().applyTheme` 做从点击点扩散的圆形动效并即时保存（写入 `StorageCache('systemSetting')`）；②**组件尺寸**（`size`）、③**动态标题**（`showDynamicTitle`）、④**系统水印**（`showWatermark`）、⑤**路由转场**（`transition`，6 选 1）均为预览式（`v-model` 直接绑定 `settingStore` 字段），由底部「保存设置」按钮统一 `saveSetting()` 落盘（保存整个 `SystemSetting` 状态，故 `size` 等同样持久化）；「重置设置」经 `resetSetting()` 清缓存 + reload。移动端 `html[data-device='mobile']` 覆盖（行纵向堆叠、按钮满宽）。
- **全局水印（el-watermark）**：`src/layout/index.vue` 以 `<el-watermark>` 包裹整个布局（`Navbar` + `router-view`），全站业务页自动带水印、业务代码零侵入。配置：`content` 经 `computed(() => settingStore.showWatermark ? VITE_APP_TITLE : [])` 绑定，受设置页「系统水印」开关控制（关闭时不渲染水印内容、仅留无害空层），取值为 `import.meta.env.VITE_APP_TITLE`（与 `index.html` 的 `%VITE_APP_TITLE%`、AppLogo 的默认 `title` 同源）；`class="wh-full"` 铺满；`gap=[16,16]` 控制平铺密度；`font` 经 `computed` 绑定 `useTheme().isDark`——暗色 `rgba(255,255,255,.15)` / 亮色 `rgba(0,0,0,.15)`，主题切换时随 `el-watermark` 内部 watch 实时重绘。组件经 `unplugin-vue-components` + `ElementPlusResolver` 按需解析（类型已自动注册 `ElWatermark`），接入零成本；默认 `z-index:9` 低于 EP 弹窗（2000+），不遮挡对话框/消息。
- **全局组件尺寸生效链路**：`size` 取自 `SystemSetting.size`（`default | small | large`），由 `useSettingStore` 暴露；`src/App.vue` 以 `<el-config-provider :size="settingStore.size">` 包裹根组件，将尺寸注入 Element Plus 全局，所有 `<el-xxx>` 组件尺寸即时随 store 变化；设置页修改并经 `saveSetting()` 落盘后，刷新仍保持。同一 `<el-config-provider>` 还注入了 `element-plus` 的 `zh-cn` 语言包（仅 EP 组件文案中文化，属组件库配置，非业务文案 i18n）。

- **布局组成（AppMain 内容区出口）**：`src/layout/index.vue` 组合「`el-watermark`（全站水印）+ `Navbar`（头部）+ `AppMain`（内容区）」三层；其中 `AppMain`（`src/layout/components/AppMain/index.vue`）是从布局内联 `<RouterView>` **抽出的独立积木块**，职责单一——只负责「嵌套路由出口 + 路由转场」，不包含 Navbar / 水印（由父级 `layout` 负责）。要点：①语义化 `<main class="app-main">` 包裹出口；②`RouterView` 经 `v-slot` 取 `{ Component, route }`，外层 `Transition :name="settingStore.transition" mode="out-in"` 驱动路由转场（动效名来自 `SystemSetting.transition`，默认 `fade-transform`，自定义类在 `src/styles/transition.scss`，其余 `el-fade-*`/`el-zoom-*` 为 EP 内置）；③`<component :key="route.path">` 按 path 强制重挂载（同上注释，`path` 比 `fullPath` 更通用）；④`KeepAlive :include="[]"` 当前为空数组、是缓存能力的**占位 no-op**，尚未接 cachedViews 名单；⑤样式仅 `position:relative; width:100%; overflow:hidden`，无 `flex:1`/高度/纵向滚动，依赖内容自然撑开、整页在 body 级滚动（与「业务页用 `.app-content` 自带 padding」的模型一致）；⑥无图标 / `@/utils` 散装依赖，`useSettingStore` 走 `dirs:['src/store/modules']` 自动导入，符合 AGENTS.md 约定。

## 七、首屏体验

- **首屏加载动画（白屏兜底）**：`#app` 内放纯 HTML+CSS spinner，`main.ts` 不手动删节点，靠 `app.mount` 原生清空自动消失，JS 加载期间不再白屏、体验更顺。
