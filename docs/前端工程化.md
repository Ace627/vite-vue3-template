# 前端工程化配置

> 基于 `pnpm create vite` 的 Vue3 + TS 模板二次改造，以下为已实现的工程化配置。每条后用一句话说明它带来的好处。本文是 [`README.md`](../README.md) 中"前端工程化实践样本"的**配置详解**：样本展示"配了什么、为什么、收益几何"，这里逐条展开。

## 零、前端工程化解决了什么问题

当项目从「一个人写几页」长成「一个团队维护成千上万行、还要持续交付」时，靠人肉约定再也撑不住。前端工程化就是把「靠人自觉」变成「靠系统兜底」——它不是某一项技术，而是一整套让「开发 — 构建 — 协作 — 交付」可重复、可预期的体系，主要应对以下六类问题：

| 工程化前痛点 | 工程化解法 | 本模板对应能力 |
| --- | --- | --- |
| 文件混乱、全局变量污染 | 模块化 / 组件化 / 目录约定 | 路径别名 `@/`、AGENTS.md 目录约定、组件化分层 |
| 改一行刷新整页 | Dev Server + HMR 热更新 | Vite 极速 HMR |
| 手写重复样板代码 | 脚手架 + 自动导入 + UI 库 | unplugin 自动导入、Element Plus、SvgIcon |
| 上线慢、包体大 | 打包 / Tree-shaking / 分包 / 压缩 | vendor 分包、gzip 预压缩、drop console/debugger |
| 运行时才报错 | TypeScript + Lint + 单测 | 严格 TS、oxfmt、vue-tsc 校验 |
| 协作风格打架 | 规范 + Git Hooks | AGENTS.md 约束、oxfmt（husky 待补） |

下文逐条展开本模板已落地的工程化配置与其收益。

## 一、构建与产物优化

- **构建期 vendor chunk 分包（Rolldown `codeSplitting.groups`）**：把 `vue/pinia/vue-router/axios/dayjs` 拆成独立带 hash 的 chunk，库代码不随业务发版变动，二次访问命中浏览器长缓存、免重下，首屏多块并行下载更快；拆分收益与命名规则见 `构建与工程化/构建文件拆分.md`。
- **构建期 gzip 预压缩（vite-plugin-compression2）**：对 >10KB 的 JS/CSS/JSON/HTML/SVG 生成 `.gz` 预压缩文件（保留原文件），传输体积降约 61%（vue 60.7KB→23.6KB、vue-router 22.7KB→8.9KB），首屏大资源下载更快；压缩成本前移到构建期、零运行时开销，服务端开 `gzip_static` 即直接发 `.gz`；说明见 `构建与工程化/构建期Gzip预压缩.md`。
- **构建期移除 console/debugger**：通过 Rolldown `minify.compress.dropConsole/dropDebugger` 在打包时剔除调试语句，生产包更干净、体积更小（可用 `VITE_DROP_*` 关闭）；说明见 `构建与工程化/构建期移除调试语句.md`。
- **Vite 插件抽离**：vue / UnoCSS / 自动导入 / SVG 等插件统一在 `build/plugins/index.ts` 注册，配置集中可维护，且纳入 `tsconfig.node` 类型检查；独立模块设计说明见 `构建与工程化/Vite插件独立模块设计.md`。

## 二、类型与代码质量

- **严格 TypeScript 配置**：开启 `noUnusedLocals/Parameters`、`erasableSyntaxOnly`，`tsconfig.node` 用 `verbatimModuleSyntax/nodenext`，编译期即拦掉未用变量与错误模块写法，减少低级 bug。
- **oxfmt 统一格式化**：固定 `printWidth/singleQuote/semi/trailingComma` 等规则（import 排序当前未启用），团队提交风格一致，`format:check` 可作格式门禁。
- **脚手架清理**：移除 Vite 默认样板冗余，保留最小可运行骨架，模板更干净、上手更快。

## 三、开发体验

- **路径别名 `@/*`**：`@` 直指 `src`，深层引用不再写 `../../`，tsconfig 与 vite alias 双向同步；详见 `构建与工程化/路径别名.md`。
- **unplugin 自动导入**：`vue/pinia/vue-router` 及 `store/modules`、`hooks` 免手写 import，减少样板、避免遗漏。
- **开发期反向代理**：把「代理触发前缀」与「后端公共路径」合一于 `VITE_BASE_API` 一个变量，开发消跨域、切环境/换后端只动 `.env`，业务代码零改动；详见 `构建与工程化/开发环境反向代理.md`。
- **多环境 `.env`**：dev/prod 分别提供后端地址、超时、丢弃调试等变量，`index.html` 用 `%VITE_APP_TITLE%` 原生注入，环境切换零代码改动。

## 四、状态管理与路由

- **Pinia 状态管理**：`createPinia()` 单例 + `setupStore(app)` 统一装配，状态层结构清晰、便于测试与维护；当前含 `app` / `setting` / `user` / `permission` / `tags-view` 五个 store。
- **vue-router 三层结构 + 登录态守卫**：①`src/router/index.ts` 异步 `setupRouter(app)`（注册守卫→`app.use(router)`→`await router.isReady()` 再挂载），`VITE_ROUTER_MODE` 切换 hash/history；②`src/router/modules/static.route.ts` 抽离常量路由 `STATIC_ROUTE_LIST`（`Layout` 为布局父路由，含 `dashboard` / `login` / `redirect` / `404` 通配，无动态权限）；③`src/router/router.guard.ts` 的 `globalRouterBeforeGuard` 统一登录态拦截——白名单 `/login` 直接放行，已登录访问 `/login` 重定向首页，无 token 跳 `/login?redirect=原路径`；**已登录但无角色时拉取用户信息并生成路由**：`userStore.getInfo()` 拿到 `roles/permissions`，`permissionStore.getRoutes()` 构建可访问路由，再 `router.addRoute('Layout', …)` 注入（当前 `dynamicRouteList` 为空，仅静态路由，`asyncRoutes` 接真接口为预留），登录后自动回跳。受保护页无需各自判权限，路由层兜底。
- **登录 / 登出（mock 实现）**：登录链路已 mock 重构——`src/api/auth.request.ts` 的 `AuthRequest` 提供 `getCaptcha/login/getInfo/logout` 的**写死数据**实现（真实 `request.*` 调用已注释，均不发出网络请求）；`login.vue` 含验证码 + 「记住密码」（`login-params.cache` 缓存用户名密码），提交后 `userStore.login` 写死 token 并 `getInfo` 拉取角色权限，跑通「无 token→拦登录→登录→回跳→登出清 token」整链；`user` store 落地 `currentUserInfo / roles / permissions / avatar`，`logout` 清 token。目前是前端模拟（不调真实接口、账号密码/验证码不校验、角色权限来自 mock 数据），接真实后端只需放开 `auth.request.ts` 的 `request.*` 调用并保留 `user` store 与权限指令即可；用户体系详细说明见 `UI组件/用户体系.md`。

## 五、请求层

- **axios 请求层**：统一实例 + `jwt-auth` / `response-transform` / `response-error` 三拦截器，成功自动解包 `data`、业务失败与 401 自动清 token 刷新；`ApiResponse<T>` 契约让调用方直接 `get<User>` 拿到业务数据，类型全程收紧。

## 六、样式与 UI

- **UnoCSS**：`presetWind3 + presetAttributify` + 自定义 rules/shortcuts，原子化开发、编译期摇树，无运行时 CSS 框架体积。
- **样式分层（reset.css）**：`reset.css` 经 `<link>` 引入不进打包，避免 FOUC（样式闪烁），全局样式入口 `index.scss` 独立清晰。
- **业务路由页基础容器 `.app-content`**：`src/styles/index.scss` 定义 `.app-content`（`position:relative; width:100%; padding:16px`），移动端 `html[data-device='mobile']` 收窄为 `12px`；所有挂载在 layout 内的业务路由页根元素统一加该类，页面内不再各自写 `padding`/`min-height`，保证内边距体验一致；移动端断点由 `src/hooks/useResize.ts` 在 `App.vue` 挂载时监听窗口宽度（阈值 992px），将 `appStore.device` 写入 `html[data-device]`，驱动各处的 `html[data-device='mobile']` 覆盖样式（如 `.app-content` 收窄、设置页行纵向堆叠）；设备自适应（响应式断点）说明见 `响应式/设备自适应.md`。
- **SVG 图标（SvgIcon）**：`vite-plugin-svg-icons` 通过 `virtual:svg-icons-register` 运行时注入 sprite，组件按文件名引用图标；新增图标走清理脚本适配 `currentColor`，单色图标随主题变色；SvgIcon 图标方案说明见 `UI组件/SvgIcon图标.md`。
- **Element Plus（按需引入 + sass 主题 + 暗黑 css-vars + 主题切换开关）**：两插件互补、缺一不可。`unplugin-vue-components` + `ElementPlusResolver({ importStyle: 'sass' })` 负责**模板组件** `<el-xxx>` 与 sass 源样式按需自动导入（非全量引入，主 CSS 仅约 13KB、无 EP 独立 vendor chunk，佐证按需）；`unplugin-auto-import` 同一 resolver 仅自动导入 `ElMessage` 等 API 的**名称**。`unplugin-element-plus({ useSource: true })` 负责**函数式 API 的样式注入**——`ElMessage` / `ElMessageBox` / `ElNotification` / `ElLoading` 这类从 `'element-plus'` 显式 import 的函数，其样式 resolver 不会注入、必须靠它（曾误删导致 `ElMessage` 样式丢失，已恢复）。`vite.config.ts` 的 `additionalData` 把 `el-theme-light.scss` 的自定义主题变量（`@forward 'element-plus/theme-chalk/src/common/var.scss' with (...)`，primary `#0077ff` 等）注入每个 EP 组件样式编译完成换肤；`el-theme-dark.scss` 引入官方暗黑 css-vars（`html.dark` 下生效），已由 `Navbar` 的 `ThemeSwitch` 组件接好开关，主题切换可用；Element Plus 按需引入见 `UI组件/ElementPlus按需引入.md`，自定义主题见 `UI组件/ElementPlus自定义主题.md`。

- **统一消息反馈（TipModal）**：`src/utils/tip-modal.ts` 的 `TipModal` 抽象类把 `ElMessage`/`ElMessageBox`/`ElNotification`/`ElLoading` 四类反馈收口为统一层，全项目仅从 `@/utils` 引入 `TipModal`、杜绝散装 `import { ElMessage } from 'element-plus'`；详见 `UI组件/统一消息反馈.md`。

- **品牌标识组件（AppLogo）**：项目 Brand（logo + 应用标题）的抽离封装组件，将品牌展示从布局中独立出来，可任意拼装复用、不依赖全局状态。路径 `src/layout/components/AppLogo/`（index.vue + types.ts）；props `showTitle`（默认 `true`，如侧边栏折叠时传 `false` 只显示图标）/`title`（默认 `import.meta.env.VITE_APP_TITLE`）；logo 用 `<img src="/favicon.svg">` 加载品牌图（属品牌图、非 UI 功能图标，不冲突 SvgIcon 规范）；当前 Sidebar 中以 `<AppLogo :show-title="!appStore.isCollapse" />` 使用（侧栏折叠时只显示图标）。

- **全局设置中心（SystemSetting）**：`src/defaultSettings.ts` 定义 `SystemSetting` 类型与默认值，共 9 项——`theme`（主题）、`size`（组件尺寸）、`showDynamicTitle`（动态标题）、`uniqueOpened`（侧边栏手风琴）、`showWatermark`（系统水印）、`showLogo`（显示 Logo）、`showTagsView`（多标签模式）、`showTagsViewIcon`（显示页签图标）、`transition`（路由转场）；`store/modules/setting.ts` 的 `useSettingStore` 用 `merge(defaultSettings, getSystemSetting())` 初始化，暴露各字段 + `saveSetting`（落盘到 `StorageCache('systemSetting')`）/ `resetSetting`（清缓存 + reload）/ `isDark` / `showSetting`（控制配置抽屉显隐）；全站配置经此单一出口读写与持久化；全局设置中心说明见 `构建与工程化/全局设置中心.md`。

- **主题切换（亮 ↔ 暗）**：`src/hooks/useTheme.ts` 的 `useTheme()` 是主题切换的**统一逻辑层**——Navbar 的 `ThemeSwitch` 委托它，负责命令式同步 `html.dark` 类、View Transitions API 圆形扩散动效（有点击坐标从点击点扩散、无坐标从屏幕中心）、防 FOUC 初始化、非 Chromium 浏览器自动降级；持久化经 `saveSetting` 写入 `StorageCache('systemSetting')`（刷新后保持）；主题切换说明见 `用户体验/主题切换.md`。

- **系统布局配置（SettingPanel 抽屉）**：`/settings` 独立路由页已移除，改为全局配置抽屉——Navbar 齿轮图标与用户菜单「系统设置」均将 `settingStore.showSetting` 置 `true`，唤起 `src/layout/components/SettingPanel/index.vue`（`el-drawer` 右侧抽屉）。抽屉内以 `el-switch` / `el-select` **双向绑定 `settingStore` 各字段**（动态标题 / 显示 Logo / 手风琴菜单 / 系统水印 / 多标签模式 / 显示页签图标 / 页面转场动效），底部「保存配置」「重置配置」按钮分别调 `saveSetting()` / `resetSetting()` 统一落盘或清空刷新；主题切换仍走 `useTheme()` 即时保存（见上）。移动端抽屉 `size="280px"` 自适应；全局设置中心（数据 / 持久化层）说明见 `构建与工程化/全局设置中心.md`。

- **系统级水印（el-watermark）**：`src/layout/index.vue` 以 `<el-watermark>` 包裹整个布局，全站业务页自动带水印、业务代码零侵入；`content` 受「系统水印」开关控制（关闭仅留空层），`font` 随主题明暗联动；系统级水印说明见 `用户体验/系统级水印.md`。

- **全局组件尺寸生效链路**：`size` 取自 `SystemSetting.size`（`default | small | large`），由 `useSettingStore` 暴露；`src/App.vue` 以 `<el-config-provider :size="settingStore.size">` 包裹根组件，将尺寸注入 Element Plus 全局，所有 `<el-xxx>` 组件尺寸即时随 store 变化；SettingPanel 抽屉内修改并经 `saveSetting()` 落盘后，刷新仍保持。同一 `<el-config-provider>` 还注入了 `element-plus` 的 `zh-cn` 语言包（仅 EP 组件文案中文化，属组件库配置，非业务文案 i18n）。

- **布局组成（Layout 骨架）**：`src/layout/index.vue` 组合「`el-watermark`（全站水印）+ `Sidebar`（左侧菜单）+ `Navbar`（顶部：折叠 / 设置入口 / 主题切换 / 用户菜单）+ `TagsView`（多页签，受 `showTagsView` 控制）+ `AppMain`（内容区）+ `SettingPanel`（配置抽屉）」六块。其中 `AppMain`（`src/layout/components/AppMain/index.vue`）是从布局内联 `<RouterView>` **抽出的独立积木块**，职责单一——只负责「嵌套路由出口 + 路由转场」，不包含 Navbar / 水印（由父级 `layout` 负责）。要点：①语义化 `<main class="app-main">` 包裹出口；②`RouterView` 经 `v-slot` 取 `{ Component, route }`，外层 `Transition :name="settingStore.transition" mode="out-in"` 驱动路由转场（动效名来自 `SystemSetting.transition`，默认 `fade-transform`，自定义类在 `src/styles/transition.scss`，其余 `el-fade-*`/`el-zoom-*` 为 EP 内置）；③`<component :key="route.path">` 按 path 强制重挂载（同上注释，`path` 比 `fullPath` 更通用）；④`KeepAlive :include="[]"` 当前为空数组、是缓存能力的**占位 no-op**，尚未接 cachedViews 名单；⑤样式仅 `position:relative; width:100%; overflow:hidden`，无 `flex:1`/高度/纵向滚动，依赖内容自然撑开、整页在 body 级滚动（与「业务页用 `.app-content` 自带 padding」的模型一致）；⑥无图标 / `@/utils` 散装依赖，`useSettingStore` 走 `dirs:['src/store/modules']` 自动导入，符合 AGENTS.md 约定。侧边栏 / 多页签 / 用户菜单分别见 `UI组件/侧边栏菜单.md`、`UI组件/多标签页面签.md`、`UI组件/导航栏用户菜单.md`。

## 七、首屏体验

- **首屏加载动画（白屏兜底）**：`#app` 内放纯 HTML+CSS spinner，`main.ts` 不手动删节点，靠 `app.mount` 原生清空自动消失，JS 加载期间不再白屏、体验更顺。

## 八、工程化 Skill

- **4 个项目 Skill（git-commit-msg / path-alias / add-global-component / iterate-docs）**：把「提交规范」「别名配置」「新增全局组件」「根据代码改动迭代 docs」等固定流程沉淀为可复用技能，照着走不踩坑、减少重复决策；`iterate-docs` 负责根据最新改动的代码完善、迭代 `docs/` 下的文档，让文档始终与真实代码保持一致。
