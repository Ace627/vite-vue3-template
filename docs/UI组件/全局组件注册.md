# 全局组件注册

## 功能定位

项目对「需全局可用的自定义组件」（当前含 `SvgIcon` / `ProPagination` / `ProTable`）采用显式注册 + 手写类型声明的方式接入，而非依赖 `unplugin-vue-components` 的目录扫描自动注册。本文只谈「全局组件的注册与类型声明」以及「为何 components 的 `dirs` 留空」，不涉及组件内部实现（`SvgIcon` 见 `UI组件/SvgIcon图标.md`；`ProPagination` / `ProTable` 为 Element Plus 封装，内部实现见各自源码，其中 `ProTable` 另有 `UI组件/ProTable组件.md`）。

## 实现要点

| 落地点 | 职责 |
| --- | --- |
| `src/plugins/modules/global-component.ts` | `registerGlobalComponent(app)` 内依次 `app.component('SvgIcon', SvgIcon)` / `app.component('ProPagination', ProPagination)` / `app.component('ProTable', ProTable)`，把三者注册为全局组件 |
| `src/plugins/index.ts` | `setupPlugins(app)` 中 `app.use(registerGlobalComponent)`，随应用启动注册 |
| `src/main.ts` | `bootstrap()` 调用 `setupPlugins(app)`，注册发生在 `mount` 之前 |
| `src/types/global/global-component.d.ts` | **手写** `declare module 'vue' { interface GlobalComponents { SvgIcon / ProPagination / ProTable: ... } }`，为模板中的 `<SvgIcon>` / `<ProPagination>` / `<ProTable>` 提供类型 |
| `build/plugins/auto-import-plugin.ts` 的 `registerAutoComponents` | `unplugin-vue-components` 配置 `dirs: []`，仅作 Element Plus 解析器，不扫描自定义组件目录 |

### 机制

- 运行期：所有全局组件在 `setupPlugins` 阶段被 `app.component` 注册，之后所有模板（含 `.vue` SFC 与 JSX）均可直接使用 `<SvgIcon>` / `<ProPagination>` / `<ProTable>` 而无需 `import`。
- 类型期：`global-component.d.ts` 通过扩展 Vue 的 `GlobalComponents` 接口，让模板里的 `<SvgIcon>` / `<ProPagination>` / `<ProTable>` 获得类型与属性提示；该文件是手写、非自动生成。
- `unplugin-vue-components` 自动生成的 `src/types/auto-generate/auto-components.d.ts` 只声明它从 resolver 解析到的组件（当前即 Element Plus 系列 + `RouterLink/RouterView`），不含上述自定义组件——因为自定义组件走的是手写注册通道，不在其扫描范围内。

## 好处

- 全局组件白名单式显式注册，注册了什么一目了然，不会出现「目录里某个文件被悄悄变成全局组件」的意外。
- 手写 `GlobalComponents` 声明与 `app.component` 注册一一对应，模板类型不依赖代码生成工具是否跑成功。
- 自定义组件不进 `auto-components.d.ts`，该文件只反映 Element Plus 等第三方组件，职责清晰、diff 干净。
- 新增全局组件只需在 `global-component.ts` 加一行 `app.component`、在 `global-component.d.ts` 加一条类型，改动收敛在一处。

## 工程化好处

- 第三方组件自动解析（Element Plus resolver）与自定义组件显式注册两条通道解耦，互不干扰。
- 不依赖目录扫描的隐式约定，CI 中即便自动生成步骤异常，自定义全局组件仍可用、类型仍在（构建更稳）。
- 显式注册 + 手写类型是自解释的做法，新人无需理解 `unplugin-vue-components` 的扫描规则即可接手。

## 注意事项

- 为何 `components` 的 `dirs` 留空：项目选择「自定义全局组件显式注册」而非「扫 `src/components` 全目录自动注册」。原因——避免把目录里每个组件都变成全局组件（命名冲突、全局命名空间膨胀、不可预期），也避免依赖自动生成对自定义组件的类型覆盖；Element Plus 组件仍由 resolver 自动解析，两者不冲突。
- 注册与类型要同步：在 `global-component.ts` 注册全局组件后，务必在 `global-component.d.ts` 补对应类型，否则模板里该组件无类型/属性提示。
- `global-component.d.ts` 是手写、非自动生成：不要把它误当成 `unplugin-vue-components` 的产物去删或改生成逻辑；它与 `auto-generate/` 下自动生成的 `auto-components.d.ts` 是两回事。
- 当前走此通道的组件：`SvgIcon` / `ProPagination` / `ProTable` 均为显式全局注册；其它业务组件仍按需局部引入。其中 `ProPagination`（基于 `el-pagination` 封装，双向绑定页码/页大小 + 移动端适配）与 `ProTable`（基于 `el-table` 封装，动态列 + 插槽透传 + 实例代理）的内部实现见各自源码（`src/components/ProPagination/index.vue`、`src/components/ProTable/index.vue`），`ProTable` 另有实现文档 `UI组件/ProTable组件.md`。
