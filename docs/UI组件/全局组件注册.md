# 全局组件注册

## 功能定位

项目对「需全局可用的自定义组件」（当前即 `SvgIcon`）采用 **显式注册 + 手写类型声明** 的方式接入，而非依赖 `unplugin-vue-components` 的目录扫描自动注册。本文只谈「全局组件的注册与类型声明」以及「为何 components 的 `dirs` 留空」，不涉及组件内部实现（见 `UI组件/SvgIcon图标.md`）。

## 实现要点

| 落地点 | 职责 |
| --- | --- |
| `src/plugins/modules/global-component.ts` | `registerGlobalComponent(app)` 内 `app.component('SvgIcon', SvgIcon)`，把 `SvgIcon` 注册为全局组件 |
| `src/plugins/index.ts` | `setupPlugins(app)` 中 `app.use(registerGlobalComponent)`，随应用启动注册 |
| `src/main.ts` | `bootstrap()` 调用 `setupPlugins(app)`，注册发生在 `mount` 之前 |
| `src/types/global/global-component.d.ts` | **手写** `declare module 'vue' { interface GlobalComponents { SvgIcon: ... } }`，为模板中的 `<SvgIcon>` 提供类型 |
| `build/plugins/auto-import-plugin.ts` 的 `registerAutoComponents` | `unplugin-vue-components` 配置 `dirs: []`，仅作 Element Plus 解析器，不扫描自定义组件目录 |

### 机制

- 运行期：`SvgIcon` 在 `setupPlugins` 阶段被 `app.component` 注册为全局组件，之后所有模板（含 `.vue` SFC 与 JSX）均可直接使用 `<SvgIcon>` 而无需 `import`。
- 类型期：`global-component.d.ts` 通过扩展 Vue 的 `GlobalComponents` 接口，让模板里的 `<SvgIcon>` 获得类型与属性提示；该文件是**手写、非自动生成**。
- `unplugin-vue-components` 自动生成的 `src/types/auto-generate/auto-components.d.ts` 只声明它从 resolver 解析到的组件（当前即 Element Plus 系列 + `RouterLink/RouterView`），**不含 `SvgIcon`**——因为自定义组件走的是手写注册通道，不在其扫描范围内。

## 好处

- **可控、可预期**：全局组件白名单式显式注册，注册了什么一目了然，不会出现「目录里某个文件被悄悄变成全局组件」的意外。
- **类型与运行时一致**：手写 `GlobalComponents` 声明与 `app.component` 注册一一对应，模板类型不依赖代码生成工具是否跑成功。
- **不污染自动生成产物**：自定义组件不进 `auto-components.d.ts`，该文件只反映 Element Plus 等第三方组件，职责清晰、diff 干净。
- **注册集中、易扩展**：新增全局组件只需在 `global-component.ts` 加一行 `app.component`、在 `global-component.d.ts` 加一条类型，改动收敛在一处。

## 工程化好处

- **关注点分离**：第三方组件自动解析（Element Plus resolver）与自定义组件显式注册两条通道解耦，互不干扰。
- **构建健壮**：不依赖目录扫描的隐式约定，CI 中即便自动生成步骤异常，自定义全局组件仍可用、类型仍在。
- **可复制范式**：显式注册 + 手写类型是自解释的标准做法，新人无需理解 `unplugin-vue-components` 的扫描规则即可接手。

## 注意事项

- **为何 `components` 的 `dirs` 留空**：项目选择「自定义全局组件显式注册」而非「扫 `src/components` 全目录自动注册」。原因——避免把目录里每个组件都变成全局组件（命名冲突、全局命名空间膨胀、不可预期），也避免依赖自动生成对自定义组件的类型覆盖；Element Plus 组件仍由 resolver 自动解析，两者不冲突。
- **注册与类型要同步**：在 `global-component.ts` 注册全局组件后，务必在 `global-component.d.ts` 补对应类型，否则模板里该组件无类型/属性提示。
- **`global-component.d.ts` 是手写、非自动生成**：不要把它误当成 `unplugin-vue-components` 的产物去删或改生成逻辑；它与 `auto-generate/` 下自动生成的 `auto-components.d.ts` 是两回事。
- **仅 `SvgIcon` 走此通道**：目前项目唯一显式全局注册的自定义组件是 `SvgIcon`；其它业务组件按需在各自页面/布局内局部引入。
